## 1. §4 자동 JOIN 감지 시스템

| 항목 | 명세 요구 | 구현 상태 | 비고 |
|------|-----------|-----------|------|
| 1순위: FK 패턴 | information_schema FK로 `from_table, to_table, from_column, to_column` 반환 | ✅ 구현됨 | `routes.py` FK 쿼리 |
| 2순위: 동일 컬럼명·타입 | 같은 이름+같은 타입, **id/created_at/updated_at 제외** | ✅ 구현됨 | `routes.py`에서 제외 처리 적용 |
| 2순위: 참조 테이블 있으면 직접 연결 안함 | 컬럼이 `_id`로 끝나고, 참조 테이블(추론)이 테이블 목록에 있으면 해당 두 테이블 직접 연결 제외 | ❌ 미구현 | 예: deliveries.campaign_id ↔ tracking_events.campaign_id 시 campaigns 존재하면 둘을 campaign_id로 연결하지 않음 |
| 3순위: 데이터 샘플링 | 1000건 샘플, 겹침 비율 70%+ → 관계 제안 | ❌ 미구현 | - |
| confidence | HIGH(FK) / MEDIUM(동일컬럼) / LOW | ✅ 구현됨 | API 응답에 포함 |
| reason | 감지 이유 문구 | ✅ 구현됨 | "FK 관계", "동일 컬럼명·타입" |
| cardinality | 1:1 / 1:N / N:1 / N:N | ⚪ 미반환 | API에서 생략, UI 영향 적음 |

## 2. §5.2 JOIN 설정 (JoinConfig)

| 항목 | 명세 요구 | 구현 상태 | 비고 |
|------|-----------|-----------|------|
| joinType | LEFT / INNER / RIGHT | ✅ 구현됨 | 테이블쌍별 선택, sqlBuilder 반영 |
| conditions | 배열 `[{ prevColumn, currColumn }]` | ✅ 구현됨 | 복합 조건 지원 |
| logicalOperator (조건 간 AND/OR) | AND / OR | ⚠️ AND만 지원 | ON 절이 `cond1 AND cond2`만 생성, OR 미지원 |
| JoinCondition.operator | = / != / > / < 등 | ⚪ = 만 사용 | ON 절은 현재 `=` 만 사용 (명세 예시도 = 위주) |

## 4. §5.3 필터 (WHERE)

| 항목 | 명세 요구 | 구현 상태 | 비고 |
|------|-----------|-----------|------|
| 연산자 | =, !=, >, <, >=, <=, BETWEEN, IN, LIKE, IS NULL, IS NOT NULL | ⚠️ 부분 | 상수: =, !=, >, <, >=, <=, LIKE. IN/BETWEEN/IS NULL 등은 escapeValueForSql·WHERE 생성 로직에 특별 처리 없음 |
| logicalOperator (필터 간 AND/OR) | AND / OR | ⚠️ AND만 | WHERE 절이 `clause1 AND clause2`만 생성 |

## 7. §8.2 관계 감지 로직 (2순위 상세)

| 항목 | 명세 코드 | 구현 상태 | 비고 |
|------|-----------|-----------|------|
| col.name !== 'id' | id 제외 | ✅ 구현됨 | - |
| !col.name.includes('created') / 'updated' | created_at, updated_at 제외 | ✅ 구현됨 | 'created_at', 'updated_at' 문자열로 제외 |
| col.endsWith('_id') && 참조 테이블 존재 → continue | 직접 연결 안 함 | ❌ 미구현 | 백엔드에 참조 테이블 추론 및 스킵 로직 없음 |

## 8. API 엔드포인트 (§18 vs 실제)

명세는 Node/Express 경로 예시이고, 현재는 Flask + 다른 경로 사용.

| 명세 예시 | 실제 구현 | 비고 |
|-----------|-----------|------|
| GET /api/schema/analyze | GET /api/list-tables + POST /api/describe-table | 테이블/컬럼 정보 제공 |
| POST /api/relationships/detect | GET /api/table-relationships?mode=fk\|column\|all | 관계 감지, mode로 FK/동일컬럼/전체 |
| POST /api/query/execute | POST /api/execute-query | 쿼리 실행 |
| /api/schema/validate (명명 규칙) | ❌ 없음 | - |
| /api/relationships/validate-composite | ❌ 없음 | - |
| /api/relationships/overlap | ❌ 없음 | - |

## 9. Phase별 요약 (§9 구현 우선순위)

| Phase | 핵심 요구 | 구현 상태 |
|-------|-----------|-----------|
| Phase 1 MVP | 스키마 조회, FK 감지, LEFT JOIN 단일 조건, 기본 UI | ✅ 충족 |
| Phase 2 필터·집계 | WHERE, GROUP BY, 집계함수, ORDER BY, LIMIT | ✅ 충족 |
| Phase 3 고급 JOIN | 동일 컬럼명(2순위), JOIN 타입 선택, 복합 조건 | ✅ 대체 충족 (2순위 참조테이블 스킵 제외) |

## 10. 권장 보완 사항 (우선순위)

1. **2순위 “참조 테이블 있으면 직접 연결 안 함”**  
   - 컬럼명이 `_id`로 끝날 때 참조 테이블(예: `campaign_id` → `campaigns`)을 추론하고, 해당 테이블이 허용 목록에 있으면 그 두 테이블 간 “동일 컬럼명” 관계를 추가하지 않기.

2. **필터**  
   - IN, BETWEEN, IS NULL, IS NOT NULL 지원 시:  
     - UI에 연산자 추가  
     - `escapeValueForSql` 및 WHERE 절 생성에서 연산자별 분기 처리.

3. **WHERE/HAVING logicalOperator**  
   - 필터/HAVING 간 OR 지원 시:  
     - 상태에 logicalOperator 저장  
     - sqlBuilder에서 `AND`/`OR`로 절 연결.

4. **JOIN 조건 logicalOperator**  
   - ON 절에서 조건 간 OR가 필요하면:  
     - joinConfig에 logicalOperator 추가  
     - sqlBuilder에서 `ON (cond1 OR cond2)` 형태 생성.

5. **선택**  
   - 3순위 데이터 샘플링, 명명 규칙 검증 API, 관계 다이어그램은 명세에는 있으나 현재 범위 밖으로 두고, 필요 시 단계적으로 추가.

---

**결론**: JOIN 자동 감지(1·2순위), JOIN 타입·복합 조건, 신뢰도/ reason, 필터·집계·정렬·페이지네이션은 명세와 대체로 일치하게 구현되어 있음. **2순위 “참조 테이블 있으면 직접 연결 제외”** 와 필터 연산자(IN/BETWEEN/IS NULL 등)·AND/OR 연결이 명세와의 주요 갭이다.
