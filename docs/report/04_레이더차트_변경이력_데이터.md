# 레이더 차트 변경 이력 데이터 (ChartWidget2.jsx)

대화·수정 이력을 요소별로 데이터화해 분석하고, 최적 속성값 도출에 사용한다.

---

## 1. 요소별 변경 이력 표

| 회차 | 변경 요소 | 적용값 | 결과(관찰) |
|------|-----------|--------|------------|
| 1 | PolarRadiusAxis | domain=[0, dataMax], ticks=[0, step, 2*step, 3*step, dataMax], 커스텀 tick 컴포넌트(중심 쪽 -38px) | 반지름 숫자 순서 뒤바뀜(0이 187,283 위 등), 틱 겹침 |
| 1 | PolarAngleAxis | 커스텀 tick(바깥 +14px) | 각도 레이블·반지름 숫자와 거리 미흡, 일부 겹침 |
| 1 | Context/래퍼 | RadarChartCenterContext, ResizeObserver로 (cx,cy) 계산 후 틱 오프셋 | 방향 계산 복잡, 레이아웃 불안정 |
| 1 | margin | top/right/left 100, bottom 200 | 하단 여백 큼에도 범례가 각도 레이블과 겹침 |
| 1 | Legend | `<Legend />` 차트 내부, wrapperStyle paddingTop 28 | "발송요청"이 하단 스포크·Birthday Cam 등과 겹침 |
| 2 | PolarRadiusAxis | domain=[0, dataMax]만, ticks 제거, 기본 tick 렌더, tickFormatter만 사용 | **동일 현상 유지**: 숫자들이 상단 중앙에 수직 겹침, 순서 여전히 비정상(93,642 / 46,821 / 0 / 187,283) |
| 2 | PolarAngleAxis | 커스텀 제거, 기본 렌더 | 상단 카테고리 레이블이 반지름 숫자와 여전히 인접·겹침 |
| 2 | Legend | 차트 내부 Legend 제거, 상단 legendRow만 사용 | 스크린샷 기준 하단에 범례 겹침 여전히 보고됨(캐시/빌드 차이 가능) |
| 2 | margin | 56, 56, 56, 56 | 동일 |
| 3 | PolarRadiusAxis | tick={false}, domain만 | 반지름 숫자 전부 제거 → 스케일 파악 어려움(사용자 요청: 대략적 수치 희망) |
| 3 | PolarRadiusAxis | **내부 링만 틱** ticks=[0, dataMax/4, dataMax/2, 3*dataMax/4], 커스텀 틱으로 **각도 분산** (270°, 342°, 54°, 126°) | 바깥쪽(dataMax) 레이블 제거로 각도축과 겹침 방지, 4개 수치만 표시·서로 겹치지 않음 |

---

## 2. 외부 요인 정리 (Recharts 동작)

- **PolarRadiusAxis**: 기본 동작으로 **한 각도(angle=90) 위에만** 모든 틱 레이블이 그려짐 → 상단 중앙에 수직 겹침 필연.
- **domain/ticks**: 커스텀 domain·ticks 사용 시 타입/순서 이슈 보고됨(Recharts 이슈). 순서 꼬임 가능.
- **범례**: 차트 내부 `<Legend />` 사용 시 위치를 차트 하단 중앙으로 두어 각도축 하단 레이블과 겹치기 쉬움.

---

## 3. 분석 결론 및 최적 속성

| 요소 | 결론 | 최적 적용값 |
|------|------|-------------|
| 반지름축 숫자 | 겹침·순서 문제는 한 각도에만 그려지는 기본 동작 때문. 바깥 링만 제거·내부만 표시·각도 분산 시 해결. | **내부 4단계만** `ticks=[0, dataMax/4, dataMax/2, 3*dataMax/4]`. 커스텀 틱으로 270°/342°/54°/126°에 분산. 바깥쪽(dataMax) 레이블 없음. |
| 각도축 | 기본 렌더 유지. 커스텀 오프셋은 복잡도 대비 개선 불안정. | 기본 `PolarAngleAxis` + dataKey="subject", 마진으로만 여유 확보. |
| 범례 | 차트 내부 Legend는 하단 겹침 유발. | **차트 내부 `<Legend />` 미사용**. 상단 `legendRow`만 사용. |
| margin | 하단 여백 부족 시 각도 레이블·그리드와 시각적 겹침. | top/right/left 64, **bottom 72** (각도 레이블·그리드 하단 여유). |
| domain | 0 ~ max 일관성 유지. | `domain={[0, dataMax]}` 유지(틱은 비표시이므로 표시 순서 이슈 없음). |

---

## 4. 적용 요약 (코드 반영)

- **PolarRadiusAxis**: `domain={[0, dataMax]}`, `ticks=[0, dataMax/4, dataMax/2, 3*dataMax/4]`(바깥 링 제외). 커스텀 `RadarRadiusAxisTickInner`로 각 틱을 270°/342°/54°/126°에 배치해 겹침·순서 이슈 회피.
- **RadarChart**: `RadarChartWithCenter` 래퍼로 (cx, cy) 측정 후 Context 제공. `margin={{ top: 64, right: 64, bottom: 72, left: 64 }}`.
- **Legend**: 레이더 블록에서 `<Legend />` 없음. 상단 `legendRow`만 사용.
- **Tooltip**: 기존 `RadarTooltipContent`로 값·전체 이름 제공 유지.

이후 레이더 관련 수정 시 본 문서의 표 1·2를 갱신하고, 표 3의 최적값을 재검토한다.
