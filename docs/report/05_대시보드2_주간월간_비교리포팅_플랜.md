# 대시보드2 주간/월간 취합·이전 주·이전 월 비교 리포팅 플랜

## 목적

성과지표 취합자료를 **주간(weekly)** 또는 **월간(monthly)** 으로 분류하고, **이전 주** 또는 **이전 월**과 비교하여 리포팅할 수 있도록 **대시보드2**에 테스트 적용할 방안을 정리한 플랜 문서입니다.

---

## 1. 요구 배경

- 실제 성과 리포팅에서는 **주간 보고**(이번 주 vs 지난주), **월간 보고**(이번 달 vs 지난달) 형태로 비교하는 경우가 많음.
- 현재 대시보드는 **단일 기간**[시작일, 종료일]만 선택해 한 번에 한 구간 데이터만 조회·표시함.
- **비교 기간**을 함께 조회하고, KPI·차트·테이블에서 **기준 기간 vs 비교 기간**을 나란히 보여주거나 **증감/전비(%)** 를 표시하는 기능이 필요함.

---

## 2. 용어 정의

| 용어 | 설명 |
|------|------|
| **취합 주기** | 주간(weekly) 또는 월간(monthly). 리포팅 단위. |
| **기준 기간** | 사용자가 선택한 “이번 주” 또는 “이번 달”에 해당하는 [시작일, 종료일]. |
| **비교 기간** | 기준 기간에 대응하는 “이전 주” 또는 “이전 월” [시작일, 종료일]. |
| **주간** | 월요일~일요일(ISO 8601 주) 또는 프로젝트 정책에 따른 7일 구간. 본 플랜은 **월~일** 기준 제안. |
| **월간** | 해당 월 1일 ~ 말일. |

---

## 3. 기능 요약

- **모드 선택**: [일반 보기] / [주간 비교] / [월간 비교] 중 선택.
- **일반 보기**: 현재와 동일. 기간 [시작일, 종료일] 하나만 선택해 단일 데이터 조회·표시.
- **주간 비교**: “기준 주” 선택(예: 해당 주 월요일 날짜 또는 주 번호) → **기준 주** + **이전 주** 두 구간 자동 계산 → 두 구간 데이터 조회 후 비교 표시.
- **월간 비교**: “기준 월” 선택(YYYY-MM) → **해당 월** + **이전 월** 두 구간 자동 계산 → 두 구간 데이터 조회 후 비교 표시.
- **표시 방식**: KPI는 “기준” / “비교(이전 주·이전 월)” / “증감” 또는 “전비(%)” 열 추가. 차트·테이블은 나란히 두 기간 표시 또는 증감/전비 강조.

### 3.2 다중 이전 주·이전기간 평균 (이미지 스타일) — 구현 가능

- **요약**: 이전 주 하나가 아니라 **여러 이전 주**를 함께 보여주고, **이전기간 평균**을 기준선으로 두는 방식은 **구현 가능**합니다.
- **구성 요소**: (1) 현재 값 + "n% vs 이전기간" — 이전기간 = 직전 1주 또는 과거 N주 평균. (2) 미니 트렌드 라인 차트 — 최근 N주(예: 4~8주) 각 주의 지표값 추이. (3) 이전기간 평균선 — 트렌드 차트 위 수평 점선.
- **데이터**: 주간 비교 시 현재 주 1회 + 이전 주 1회 + 트렌드용 과거 N주 각 1회 getDashboard2Data 호출. 프론트에서 N주 평균·전비(%) 계산.
- **적용 순서**: Phase 1~5로 이번 주 vs 이전 주 먼저 적용 후, **Phase 6**에서 N주 트렌드 + 이전기간 평균 + 미니 차트 추가 권장.

## 4. 데이터·API 방안

### 4.1 옵션 A: 프론트 2회 호출 (우선 권장)

- **동작**: 취합 주기 + 기준 주/월 선택 시, 프론트에서 **기준 기간 [s1,e1]** 과 **비교 기간 [s2,e2]** 를 계산한 뒤, 기존 `POST /api/dashboard2/data` (및 필요 시 `chart-data`)를 **각각 한 번씩** 호출.
- **장점**: 백엔드 수정 없이 구현 가능. 기존 API·대시보드 서비스 로직 재사용.
- **단점**: 요청 2회로 인한 지연·네트워크 비용. 두 응답의 “동시성”은 거의 동일 시점이므로 실무상 허용 가능한 수준으로 가정.

**기간 계산 (프론트 유틸)**

- `shared/utils/dateRange.js` 확장(또는 `dashboard2/utils/periodCompare.js` 신규):
  - **주간**: `getWeekRange(anchorDate)` → 해당 주 월~일 [시작, 종료], `getPreviousWeekRange(anchorDate)` → 이전 주 [시작, 종료]. (anchorDate: 해당 주의 월요일 또는 임의 일자.)
  - **월간**: `getMonthRange(YYYY, MM)` → 해당 월 1일~말일, `getPreviousMonthRange(YYYY, MM)` → 이전 월 1일~말일.

### 4.2 옵션 B: 백엔드 비교 전용 API 1회

- **동작**: `POST /api/dashboard2/compare` 신규. body 예: `{ period_type: 'week'|'month', base_week: 'YYYY-MM-DD' }` (해당 주 월요일) 또는 `{ period_type: 'month', base_month: 'YYYY-MM' }`. 응답: `{ current: { kpi, aggregated_data, ... }, previous: { kpi, aggregated_data, ... } }`.
- **장점**: 1회 왕복으로 두 기간 데이터 일괄 조회. 주/월 경계 로직을 백엔드에 두어 일관성 유지 가능.
- **단점**: 백엔드·대시보드 서비스 수정 필요. 스키마·테스트·배포 부담.

**권장**: **1차는 옵션 A(프론트 2회 호출)** 로 대시보드2에만 적용해 검증 후, 필요 시 옵션 B로 전환.

## 5. 대시보드2 UI 설계 (테스트 적용)

### 5.1 상단 필터 영역 확장

- **보기 모드** (라디오 또는 탭): `일반 보기` | `주간 비교` | `월간 비교`.
- **일반 보기** 선택 시: 기존처럼 “시작일 ~ 종료일” 두 개 날짜 입력 유지.
- **주간 비교** 선택 시:
  - “기준 주” 선택: **주 선택기**(예: “2025년 1월 2주차” 또는 “해당 주 월요일” 하나 선택). 구현 단순화 시 **날짜 하나**만 선택하고, 그 날이 속한 주를 “기준 주”로 사용.
  - **비교 주** 선택: 비교할 주의 아무 날짜 선택. **비어두면 전 주**가 비교 기간으로 사용됨(디폴트).
  - 표시: “기준: YYYY.MM.DD ~ YYYY.MM.DD / 비교: YYYY.MM.DD ~ YYYY.MM.DD” (괄호 없이 간결하게).
- **월간 비교** 선택 시:
  - “기준 월” 선택: **YYYY-MM** (월 선택기).
  - **비교 월** 선택: 비교할 월(YYYY-MM) 선택. **비어두면 전 월**이 비교 기간으로 사용됨(디폴트).
  - 표시: “기준: … / 비교: …” (동일 형식).

### 5.2 주요 지표(KPI) 섹션

- **일반 보기**: 현재와 동일. 카드당 하나의 값.
- **주간 비교 / 월간 비교**:
  - 각 KPI 카드에 **3열** 또는 **2열 + 강조**:  
    - **기준**(이번 주/이번 달) | **비교**(이전 주/이전 달) | **증감** 또는 **전비(%)**.
  - 또는 카드 상단에 “이번 주 / 지난주” 라벨을 두고, 값 + 작은 글씨로 “전주 대비 +n%” 표시.
- **목표 대비 신호등**: 기준 기간 데이터로만 계산해 유지(기존 로직 재사용). 비교 기간은 “참고값”으로만 표시.

### 5.3 채널별 도넛·기준별 막대·집계 테이블

- **채널 도넛**:  
  - **안 1**: 기준 기간·비교 기간 도넛을 **나란히** 두 개 배치(레이블: “이번 주” / “이전 주” 등).  
  - **안 2**: 기준 기간만 도넛, 하단 또는 옆에 “이전 주 대비” 주요 채널 증감만 텍스트/뱃지로 표시.
- **기준별 막대**:  
  - **안 1**: 그룹 막대(같은 항목에 기준·비교 두 막대).  
  - **안 2**: 기준 기간만 막대, 테이블에서 비교 기간·증감 제공.
- **집계 테이블**:  
  - 컬럼 확장: 기존 컬럼 + “비교 기간 값” + “증감” 또는 “전비(%)”.  
  - 또는 “기준만” / “비교만” 탭으로 전환해 두 테이블을 같은 영역에서 전환 표시.

우선 적용 권장: **KPI 3열(기준/비교/증감 또는 전비)** → **집계 테이블에 비교 열 추가** → 채널 도넛·막대는 2단계에서 나란히 또는 그룹 막대 적용.

### 5.4 기간 표시(PeriodLabel) 확장

- 비교 모드일 때:  
  - “기준: YYYY.MM.DD ~ YYYY.MM.DD (이번 주) / 비교: YYYY.MM.DD ~ YYYY.MM.DD (이전 주)” 형태로 한 줄 또는 두 줄 표시.  
  - `PeriodLabel`에 `compareRange`, `periodLabel`(이번 주/이전 주 등) props를 추가하거나, 대시보드2 전용 **ComparePeriodLabel** 컴포넌트로 분리.

## 6. 주/월 경계 계산 규칙 (프론트 유틸 제안)

- **주**: ISO 8601 (월요일 = 1).  
  - “해당 주 월요일” = 주어진 날짜가 속한 주의 월요일.  
  - “이전 주” = (해당 주 월요일 - 7일) ~ (해당 주 일요일 - 7일).
- **월**: 달력 월 1일 00:00 ~ 말일 23:59:59.  
  - 말일: new Date(YYYY, MM, 0).getDate() 활용.  
  - 이전 월: (MM === 1 ? YYYY-1, 12 : YYYY, MM-1).

**주의**: DB/백엔드가 사용하는 타임존과 맞출 것(예: UTC vs KST). 현재 API가 `date_range` 문자열만 받는다면 “날짜”만 맞추면 되고, 필요 시 백엔드와 “일자 경계” 정의를 맞춘다.

## 7. 페이즈별 구현 제안 (대시보드2 테스트)

| Phase | 내용 | 산출 |
|-------|------|------|
| **1** | 기간 계산 유틸 | `dateRange.js` 또는 `dashboard2/utils/periodCompare.js`: getWeekRange, getPreviousWeekRange, getMonthRange, getPreviousMonthRange. 단위 테스트 권장. |
| **2** | 필터·모드 UI | Dashboard2Header(또는 전용 CompareFilter): 보기 모드(일반/주간 비교/월간 비교), 주 선택 또는 월 선택, 비교 시 두 기간 라벨 표시. |
| **3** | 데이터 2회 조회·상태 | 주간/월간 비교 선택 시 기준·비교 [s,e] 계산 후 getDashboard2Data 2회 호출. state: `dataCurrent`, `dataPrevious` (또는 `data` / `compareData`). |
| **4** | KPI 비교 표시 | KPICards2: 비교 모드일 때 “기준 / 비교 / 증감 또는 전비(%)” 열 추가. rate 지표는 전비(%) 또는 pp(percentage point) 차이 중 정책에 맞게 선택. |
| **5** | 기간 라벨·차트·테이블 | PeriodLabel 확장 또는 ComparePeriodLabel. 집계 테이블에 비교 기간 열·증감 열. 채널 도넛·막대는 나란히 또는 그룹 막대(선택). |
| **6** | 다중 이전 주·이전기간 평균 (선택) | N주(예: 4주) 트렌드 데이터 조회, "이전기간 평균" 계산. KPI 카드에 미니 라인 차트 + 수평 점선(이전기간 평균). "n% vs 이전기간" 표시. |
