## 1. 서비스 한눈에 보기

- IBank BI(임시제목)는 마케팅 대시보드를 제공하고, 마케터용 노코드 쿼리 빌더(쿼리 스튜디오)로 CRM 리포트 데이터를 조회·집계·생성하는 데 초점을 둔다.
- 부서(조직) 단위로 계정이 나뉘고, 그 안에서 프로젝트를 선택한 뒤 대시보드·리포트(쿼리)·위젯 등 업무 화면을 쓰는 형태다.
- 최초 조직·관리자 계정은 운영사의 개발자 계정으로 부여되며 구성원은 초대로 가입한다.
- 대부분의 계정은 관리자(SA, A)가 보낸 초대를 받은 뒤, 초대 코드로 가입한다.
- 로그인은 이메일·비밀번호 인증(1차) + 이메일로 받은 인증 코드(2차)를 통해 진행되는 2단계 인증 방식이다.

## 2. 회원가입: 초대 코드로 가입

- 회원가입: 초대 코드로 가입


### 흐름 설명

1. 관리자가 보낸 메일의 링크를 열거나, 안내받은 초대 코드를 준비한다.

2. 1) 링크를 열면 화면에 자동으로 초대 코드가 입력되고, 이메일·비밀번호 등을 입력하고 가입을 완료한다.
   2) 링크가 열리지 않을 경우 회원가입 창에서 초대 코드를 직접 기입하고 가입을 진행한다.

3. 이후 로그인 화면에서 2차 인증을 거쳐 접속한다.


### 회원가입 화면 구성과 동작

1. 초대 코드
  - 메일 링크로 들어온 경우 코드가 자동으로 채워진다.
  - 입력란에 코드를 넣고 입력란 밖을 클릭(포커스 이동)하면, 코드가 유효한지 확인하고 부서·역할 안내 문구가 나타날 수 있다.

2. 이메일
  - 초대가 발송된 주소와 같아야 가입이 된다.

3. 비밀번호 / 비밀번호 확인
  - 안내 문구에 적힌 규칙(길이·영문 대·소문자·숫자·특수문자 등)을 만족해야 한다.

4. 비밀번호 조건·일치 검증
  - 누르면 두 비밀번호가 같은지·규칙을 통과하는지 미리 확인만 한다. 가입 완료 버튼은 아니다.

5. 닉네임(선택)
  - 화면에 표시될 이름에 가깝게 쓸 수 있다.

6. 가입하기
  - 가입 처리가 진행된다.
  - 성공하면 로그인 화면으로 이동하며, 안내 문구로 가입 완료를 알려 준다.


### 초대 코드 사용완료 혹은 만료 시(7일)

- 코드가 이미 사용됨·만료이면 안내 문구로 알려 준다. 이 경우 관리자에게 **새 초대**를 요청한다.

## 3. 로그인

- 로그인: 이메일·비밀번호·인증 코드(2단계)


### 로그인 화면 구성과 동작

1. 이메일 / 비밀번호
 - 이메일과 비밀번호를 입력하고 「인증 코드 받기」를 누른다.
 - 비밀번호가 맞고 계정이 사용 가능한 상태(활성)면, 등록된 이메일(또는 운영 정책에 따라 안내된 경로)로 숫자 인증 코드가 발송된다.
 - 잘못된 비밀번호, 정지·잠금된 계정이면 오류 메시지가 표시된다.

2. 인증 코드 입력
 - 이메일로 받은 숫자 인증 코드를 입력한 뒤 「로그인」을 누른다. 코드가 맞으면 접속이 완료되고 프로젝트 선택 화면(홈)으로 이동한다.
 - 「← 이메일로 돌아가기」를 누르면 다시 이메일·비밀번호 입력 단계로 돌아간다.
 - 화면 하단에는 초대 코드로 가입 화면으로 가는 링크가 있다.


### 인증 코드·인증 토큰 만료시(5분)

 - 서버에 저장된 인증 코드 유효 시간이 지나면 인증이 실패한다(기본 5분).
 - 1단계 직후 화면에 내려오는 일회용 인증 정보도 설정(분) 안에서 만료되며, 둘 중 먼저 끝나는 쪽에 막힐 수 있다.


### 가입 직후·비밀번호 변경 직후 로그인 화면

가입을 마친 직후에는 로그인 화면 상단에 「가입이 완료되었습니다. 로그인해 주세요.」가 보일 수 있다. 마이페이지에서 비밀번호를 바꾼 뒤에는 「비밀번호가 변경되어 모든 세션이 종료되었습니다. 다시 로그인해 주세요.」가 보인다(로그인 화면 플래시 영역).

## 4. 로그인 후 공통 화면

- 왼쪽 메뉴·상단 헤더·현재 위치 표시


### 네비 - 주 메뉴에 보이는 항목

1. 프로젝트
 - 누르면 참여 프로젝트 목록 화면(`/`)으로 간다.

2. 사용자 관리·권한 관리·프로젝트 관리·부서 관리
 - 계정 역할에 따라 보이거나 숨겨진다. 해당 페이지들의 자세한 설명은 [11. 관리 메뉴]에서 확인 가능하다.

3. 쿼리 스튜디오·대시보드·위젯보드
 - 프로젝트 페이지 혹은 헤더의 프로젝트 드롭다운에서 작업할 프로젝트를 먼저 선택해야 사용 가능하다.
 - 프로젝트 선택 전에는 보이지 않는다.

4. ETL
 - 데이터 연동·적재 권한이 있는 ETL 관리자 계정에만 보인다. 자세한 설명은 [10. ETL]을 본다.


### 상단 헤더 구역

1. 현재 페이지 제목
 - 지금 열려 있는 화면 이름이 좌측 상단에 표시된다.

2. 로그인 이메일
 - 접속 중인 계정 이메일 주소가 보인다.

3. 작업 프로젝트 선택
 - 드롭다운에서 고르면 이후 대상 프로젝트로 변경된다.

4. 알림
 - 종 모양 아이콘. 목록을 열고 알림 내용에 따라 수락/거절 등이 가능하며, 관련 화면으로 갈 수 있다.

5. 마이페이지
 - 닉네임 변경·비밀번호 변경·로그인 이력 확인이 가능하다.

6. 로그아웃
 - 누르면 이 브라우저 세션이 끊기고 로그인 화면으로 돌아간다.


### 가로 경로(브레드크럼)

- 상단 헤더와 콘텐츠 사이에 IBank BI / (현재 화면 이름) 형태로 지금 위치가 한 줄로 보인다.

## 5. 프로젝트(홈)

- 홈: 작업할 프로젝트 조회 및 선택.


### 프로젝트 목록 구성과 동작

1. 카드 목록
 - 참여 중인 프로젝트가 카드 형태 목록으로 제공된다(넓은 화면에서는 한 줄에 두 카드, 좁으면 한 줄에 한 카드).
 - 카드별로 프로젝트명, 프로젝트 권한(역할) 라벨·이름, 프로젝트 설명이 보인다.

2. 이 프로젝트로 작업
 - 누르면 헤더의 드롭다운이 해당 프로젝트로 지정되고, 권한에 맞는 페이지가 네비에 활성화되며 해당 페이지로 이동할 수 있다.

3. 헤더 프로젝트 드롭다운
 - 이미 선택된 작업 프로젝트가 있으면, 홈으로 돌아와도 헤더에서 바로 다른 프로젝트로 바꾸거나 같은 프로젝트로 이어 갈 수 있다.


### 빠른 액세스 목록 구성과 동작

1. 프로젝트 작업 카드
 - 작업 프로젝트를 고른 뒤에만 쿼리 스튜디오·대시보드·위젯보드 카드가 부여된 권한에 따라 나타난다.

2. 관리·인프라 카드
 - 역할에 따라 사용자 관리, 권한 관리, 프로젝트 관리, 부서 관리, ETL 바로가기가 나타난다.

## 6. 마이페이지

- 마이페이지: 내 프로필·비밀번호·로그인 이력(최근 10회)


### 화면 구성과 동작

1. 프로필(이메일·부서·역할·닉네임)
 - 이메일·소속 부서·역할은 읽기 전용이다.
 - 닉네임을 고친 뒤 「닉네임 저장」을 누르면 컨펌 창 후 서버에 반영된다.

2. 비밀번호 변경
 - 현재·새·새 확인 비밀번호를 입력해 변경한다.
 - 성공 시 **모든 기기·브라우저에서 로그아웃**되며 다시 로그인해야 한다.

3. 로그인 이력
 - 최근 기준 접속 일시, 결과 IP(마스킹) 등이 표로 보인다.

## 7. 쿼리 스튜디오

- 쿼리 스튜디오: 프로젝트에 매핑된 테이블을 선택하여 CRM 리포트 테이블을 생성한다.


### 화면 구성과 동작

1. 왼쪽(테이블·폴더)
 - 관련 폴더·매핑된 또는 사용할 수 있는 테이블이 트리 형태로 보인다.
 - 테이블별 테이블 라벨명, 컬럼 라벨명을 정의/수정할 수 있다.

2. 오른쪽(조건 조립)
 - 테이블 또는 컬럼을 드래그 앤 드롭으로 넣어서 연결된 테이블을 볼 수 있다.
 - 테이블 초기화/테이블 저장/조건·정렬·피벗·HAVING/조회 실행(자동실행)을 할 수 있다.
 - 보여지는 테이블에서 컬럼 이동/집계 등을 적용할 수 있다.

3. 아래(결과)
 - 전체 건수 조회가 가능하다.
 - 선택한 건수별(50, 100, 200, 500)로 데이터를 조회할 수 있고, 페이지 이동이 가능하다.
 - 실행된 SQL 원문 확인이 가능하다.

## 8. 대시보드

- 대시보드: 캠페인·마케팅 성과를 시각화된 데이터를 통해 확인할 수 있다.


### 화면 구성과 동작

1. 차트·지표
 - 정형화된 대시보드 데이터를 조회하여 차트·KPI카드·퍼널·데이터목록이 제공된다.

2. 기간·필터
 - 화면 상단의 날짜 필터로 보고 싶은 범위를 바꾼다.
 - 일간·주간·월간 집계기능을 제공한다. 주간은 월~일요일, 월간은 해당월 1일~말일의 집계 데이터를 제공하며, 연산은 끝점 연산법이 적용된다.
 - 전체회원수 카드, 발송대상 회원수 카드, 회원 분석 섹션은 주간·월간 집계의 영향을 받지 않고 날짜 필터의 기준일에 대한 데이터만 로드된다.

## 9. 위젯보드

- 위젯보드: 제공되는 팔레트로 위젯 아이템을 만들어 보드에 구성 및 편집한다.


### 위젯보드 진입 화면

1. 목록
 - 해당 프로젝트에 만들어 둔 보드가 목록으로 제공된다.
 - 생성한 보드, 참여중인 보드, 프로젝트 공개 보드가 보이며, 참여중이 아닌 다른 사용자의 비공개 보드는 보이지 않는다.

2. 위젯보드 생성
 - 보드명·설명·공개여부를 설정하고 새 보드를 제작할 수 있다.


### 위젯 보드 목록

1. 작업 - 캔버스
 - 해당 위젯보드에 위젯아이템을 생성 및 편집할 수 있는 실질적인 위젯보드 화면으로 이동한다.

2. 작업 - 수정
 - 해당 위젯보드 보드명·설명·공개여부를 수정할 수 있다.

3. 작업 - 초대
 - 같은 프로젝트 참여자 중 해당 위젯 보드를 보거나 편집할 수 있도록 초대할 수 있다.
 - 프로젝트 공개 범위일 경우 모든 사용자가 볼 수는 있지만, 편집은 해당 위젯보드 참여자에게만 설정 가능하므로 초대해야 한다.

4. 작업 - 비활성
 - 해당 위젯보드를 비활성화한다.
 - 비활성화된 위젯보드는 재활성 또는 삭제할 수 있다.

5. 참여자 - 목록
 - 해당 위젯보드에 참여중인 사용자의 목록을 제공한다.
 - 생성자 본인이 아닐 경우 편집/제외를 할 수 있다. 이 때 편집은 편집 가능여부를 Y/N 변경하고, 제외는 해당 위젯보드 참여자에서 제외시킨다.


### 위젯 보드 캔버스

- 목록에서 캔버스를 누르면, 해당 보드 안에 위젯을 배치·설정하는 본 화면으로 들어간다.

1. 상단(제목·안내·동작)
 - 보드 이름이 페이지 제목으로 보이고, ← 위젯보드 목록 링크로 목록 화면으로 돌아간다.
 - 편집 권한이 없으면 읽기 전용 안내가 보이며, 왼쪽에서 위젯을 끌어 놓거나 격자를 움직이는 식의 편집은 할 수 없다.
 - 새로고침을 누르면, 저장 테이블에 연결된 위젯들의 데이터를 다시 불러온다.

2. 왼쪽(위젯 팔레트)
 - KPI, 라인·막대·파이 등 차트, 레이더, 게이지, 테이블, 메모 등 유형이 목록으로 보인다.
 - 원하는 유형을 드래그하여 오른쪽 캔버스에 놓으면 테이블·조회 기간·집계 지표 등을 고르는 생성 마법사가 창이 나타난다.
 - 모든 설정을 완료하고 확인을 누르면 위젯 아이템이 보드에 생성된다.
 - 이때 사용할 수 없는 컬럼 등이 적용되어 만들어지지 않을 경우 해당 창에서 안내가 나타난다.

3. 오른쪽(캔버스·격자)
 - 생성된 위젯 아이템은 격자 위에서 위치와 크기를 조절할 수 있다(편집 권한이 있을 때).
 - 배치를 옮기거나 크기를 바꾸면, 서버에 레이아웃이 자동으로 반영되는 흐름으로 동작한다.

4. 위젯마다 할 수 있는 일
 - 위젯 아이템마다 설정 아이콘, 복사 아이콘, 삭제 아이콘이 있다.
 - 설정 아이콘을 클릭하면 생성 시 보았던 생성 마법사가 나타나고 테이블, 기간, 차트 종류, 표에 보일 열·정렬 등을 바꿀 수 있다.
 - 위젯보드용 테이블이 설정되지 않은 경우 위젯 아이템 생성이 안되지만, 이미 생성된 후 테이블이 해제된 경우 안내 문구가 표시된다.([11.3 프로젝트 관리] 참고)
 - 메모 유형은 저장 테이블이 필요 없다.

5. 기간·데이터가 안 보일 때
 - 데이터 위젯은 기본적으로 **조회 기간**에 상한이 있다(화면 상단 안내: 예를 들어 일 단위로는 최대 14일, 주·월 단위로는 최대 12주·개월 등).
 - 표시된 기간보다 넓게 잡으면 생성이 막히고 안내가 나타난다.

## 10. ETL

- ETL: 파일·외부 DB·폴더에서 데이터 가져오기


### ETL 메뉴가 보이는 계정

- 사용자 역할과 별도로 ETL 관리자로 지정된 계정에만 좌측 메뉴가 보인다.


### 화면 구성과 동작(상단 탭)

 - 각 페이지별「탭 요약 · 사용 안내」를 펼치면 단계 설명이 있다.
 - 모든 페이지에서 ETL 목록과 배치 목록을 볼 수 있다.

1. 파일 업로드
 - CSV·엑셀 등을 올리고 저장 위치를 정한 뒤 반영한다.
 - 테이블 선택 및 컬럼 매핑 모달창에서 PK 설정, 인덱스 설정, 컬럼 변환을 지원한다.

2. 타겟DB 연결
 - 데이터를 가져올 외부 소스 DB를 등록한다.
 - PostgreSQL, MySQL, Oracle 연결을 지원하며, 연결 테스트가 통과하면 등록 가능하다.
 - 선택한 소스 DB에서 특정 테이블을 선택하여 기본 제공된 내부 타겟 DB 또는 [저장DB] 페이지에서 등록한 외부 타겟 DB에 ETL 할 수 있다.
 - 테이블 선택 및 컬럼 매핑 모달창에서 컬럼 변환을 지원하며, PK와 인덱스는 가져오려는 테이블의 정보를 따른다.

3. 배치폴더 등록
 - SFTP·S3 등 폴더를 등록하고, 규칙에 맞는 파일명을 읽어 자동 적재 배치를 설정한다.

4. 저장DB 등록
 - 데이터를 적재할 외부 타겟 DB를 등록한다.
 - PostgreSQL, MySQL, Oracle 연결을 지원하며, 연결 테스트가 통과하면 등록 가능하다.

5. ETL 이력
 - 진행·완료·실패 등 상태를 보고 필요 시 항목을 지울 수 있다.

## 11. 관리 메뉴

### 11.1 사용자 관리

- 요구자격: SA·A 역할 사용가능
- 사용자 관리: 부서원·초대·계정 상태·역할 변경 등


1. 사용자 목록·초대
 - 같은 부서 사용자 목록이 제공된다.
 - 사용자 초대로 이메일·부서·역할을 정하여 새로운 사용자를 초대할 수 있다.

2. 작업 - 목록
 - 해당 사용자의 소유물을 볼 수 있다.
 - 전체이관(섹션별) 혹은 개별 이관을 통해 다른 사용자에게 이관할 수 있다. 이때 이관받을 대상은 소유가 가능한 역할(자격)이어야 한다.

3. 작업 - 변경
 - 부서·조직 역할·ETL관리자격·프로젝트 참여 및 권한을 한 화면에서 변경 가능하다.

4. 작업 - 정지·삭제
 - 해당 사용자 계정을 정지한다.
 - 정지하기 전 이관을 해야하며, 소유물이 있을 시 막힌다.
 - 정지된 사용자는 모든 세션에서 나가진다.
 - 정지 상태일 때 재활성 또는 계정 삭제가 가능하다.


### 11.2 권한 관리

- 요구자격: SA·A 역할 사용가능
- 권한 관리: 프로젝트 권한 커스텀


1. 권한 목록·생성
 - 프로젝트에 부여할 수 있는 권한 목록이 제공된다. 각 권한에는 상세권한이 묶음으로 커스텀되어 제작 가능하다.
 - 권한 생성을 통해 프로젝트에서 사용될 상세 권한 묶음을 커스텀할 수 있다.
 - 생성한 권한은 생성한 부서에 속하며 해당 부서에서 생성한 프로젝트에 적용할 때 사용된다.

2. 사용현황 - 목록
 - 해당 권한이 적용된 프로젝트 참여자 목록을 볼 수 있다.
 - 해당 창에서 프로젝트 참여자에게 적용된 권한을 수정할 수 있다.

3. 작업 - 수정
 - 해당 권한에 적용된 상세권한 추가·제거 및 권한명 수정이 가능하다.

4. 작업 - 삭제
 - 사용 중이 아닌 권한은 삭제할 수 있지만 사용 중인 경우 삭제가 막히고 안내가 보인다.


### 11.3 프로젝트 관리

- 요구자격: SA·A·O(일부) 역할 사용가능
- 프로젝트 관리: 프로젝트 만들기·수정·비활성·멤버·테이블 매핑·기능 켜기/끄기·삭제


1. 프로젝트 목록
 - SA·A는 본인이 속한 부서에 귀속된 프로젝트 전부가 목록에 나온다.
 - O는 프로젝트 관리 일부 역할을 할 수 있지만, 참여 중인 프로젝트만 보인다.
 - 비활성 프로젝트는 조직 어드민(SA·A)에게만 활성화·삭제가 보인다.

2. 프로젝트 생성
 - SA·A만 프로젝트를 신규 생성할 수 있지만, O는 생성할 수 없다.
 - 프로젝트명·설명·본인에게 줄 권한·연결 테이블·프로젝트 적용 시스템(대시보드,쿼리스튜디오,위젯보드 선택)·같은 부서원 배정·타 부서원 초대 기능이 제공된다.
 - 연결 테이블 설정은 프로젝트에 연결할 테이블을 쿼리 스튜디오용과 위젯보드용을 각각 선택 가능하다.
 - 프로젝트 적용 시스템(대시보드,쿼리스튜디오,위젯보드) 설정은 부여된 권한과 관계없이 이 프로젝트에서 해당 시스템 접근 여부를 결정한다.
 - 같은 부서원은 체크시 초대 알림과 관계없이 배정되며, 타 부서원은 초대 알림에서 수락시 프로젝트에 참여된다.

3. 작업 - 멤버 관리
 - 목록에서 프로젝트를 고른 뒤 멤버 화면으로 들어가 멤버 추가·권한 변경·멤버 강퇴를 할 수 있다.
 - 자세한 설명은 [11.4 프로젝트 멤버]를 본다.

4. 작업 - 비활성·활성
 - 비활성·재활성은 SA·A만 할 수 있다. 비활성으로 두면 참여자 업무 화면의 프로젝트 선택 등에서 해당 프로젝트가 제외된다.

5. 작업 - 수정
 - SA·A·O가 프로젝트 수정 화면에서 이름·설명을 고칠 수 있다. SA·A는 같은 화면에서 연결 테이블 설정, 적용 시스템(대시보드,쿼리스튜디오,위젯보드) 설정도 가능하다.

6. 작업 - 삭제
 - 비활성으로 둔 프로젝트에 대해 SA·A만 삭제를 진행할 수 있다.
 - 위젯보드 등 프로젝트에 연결된 데이터가 있다면 요약해 보여 준 뒤 컨펌을 거쳐 진행한다.

7. 역할별 가능한 범위 요약
 - SA·A: 프로젝트 생성/수정(연결 테이블 설정·적용 시스템 설정 포함)·비활성·활성·삭제
 - O: 참여한 프로젝트에서 이름·설명 수정과 멤버 관리(일부). 멤버에서의 제한은 [11.4 프로젝트 멤버]를 본다.


### 11.4 프로젝트 멤버

- 요구자격: SA·A·O(일부) 역할 사용가능
- 프로젝트 멤버: 참가자·초대·권한 변경


1. 멤버 목록
 - 참여 중인 사람이 표로 나온다. 초대만 보내고 수락 전인 사람은 초대중 등으로 따로 구분된다(화면 상단 안내).

2. 멤버 추가
 - 같은 부서 소속 사용자는 즉시 배정 가능하고, 타 부서 사용자는 초대를 통해 상대가 수락하면 배정된다.
 - 프로젝트 참여를 시키기 위해서는 반드시 프로젝트에서 사용될 권한이 부여되어야 한다.
 - O는 U에 대해서만 권한 변경·제외가 가능하다(본인 포함 O 이상은 불가).
 - SA·A가 본인을 제외한 경우, 본인 참여 추가 기능이 보이고, 권한을 선택한 뒤 복구할 수 있다.

3. 역할별 가능한 범위 요약
 - SA·A: 부서·프로젝트 소유 범위에서 멤버를 넓게 다룰 수 있다.
 - O: 참여한 프로젝트 내 U에 대해서만 모든 멤버 기능이 가능하다.


### 11.5 부서 관리

- 요구자격: SA 역할 사용가능
- 부서 관리: 조직 트리


1. 부서 목록
 - 부서 목록에는 부서구분(상위·하위), 상위 부서(상위 부서일 땐 '-'표시), 부서명·코드, 사용 여부 등이 나온다.
 - 상위 부서는 시스템 운영자(SA_DEV)만 추가할 수 있으므로 운영사에 요청이 필요하다.
 - SA는 본인 소속 부서(상위)에 포함된 목록만 보이며, 소속 부서의 하위 부서에 대해서만 추가 및 관리를 할 수 있다.

2. 부서 추가
 - 소속된 부서의 하위 부서를 만들 수 있다.
 - 부서명·부서코드 설정이 필요하다.

3. 작업 - 수정
 - 부서명·부서코드 변경이 가능하고, 사용·사용안함을 선택할 수 있다.
 - 일반적으로 상위 부서는 역할과 관계 없이 사용자가 사용안함 처리할 수 없다.
 - 하위 부서에 부서원이 있는 경우 다른 하위 부서로 이관할지 여부를 묻고 부서원 이관 시 사용안함 처리가 가능하지만 해당 부서에 연결된 프로젝트, 권한 등이 있는 경우 사용안함 처리할 수 없다.

4. 작업 - 삭제
 - 일반적으로 상위 부서는 역할과 관계 없이 사용자가 삭제할 수 없다.
 - 하위부서에 프로젝트, 권한, 부서원 등이 연결되어 있는 경우 삭제할 수 없다.

   - 관리자에 의해 조직 역할(자격) 또는 프로젝트 권한(멤버 권한 템플릿 등)이 변경된 경우, 당사자에게 앱 내 알림과 함께 이메일로 변경 사실을 알리는 기능을 개발한다(변경 주체·항목 요약·문의 경로 등은 정책에 맞게 정한다).

### 12.3 시스템 로그·감사(정책·고도화 메모)

1) **목적·분리**: 사용자 액션으로 유발된 접근을 **`system_log`**에 남긴다. 스케줄 ETL 자동 실행은 **ETL 전용 이력**에만 두고 `system_log`에는 넣지 않는다.  
2) **스키마·적재**: `system_db`의 **`system_log`** append-only, `action_kind`·`business_action`·`channel`·상관 ID·IP 마스킹·UA 요약 등 — DDL·인덱스는 **04 §13**, 채널·계측 위치는 **`22` §6** 및 구현 코드.  
3) **고위험 작업**: `business_action`·`target_summary`·`risk_tier` 등으로 정지·프로젝트 비활성·멤버 제외 등을 식별·조회한다(이미 스키마·일부 UI에 반영).  
4) **SQL 원문**: 1차는 지문·템플릿 키 중심(원문 비저장 원칙, `22` §2·§4).  
5) **DB 감사 확장**: PostgreSQL 감사 확장 등 앱 외 접속 보완은 운영 정책에 따른 **선택**(`22` §9).  
6) **보존 만료·파티션**: 월 파티션·아카이브·만료 배치는 **추후 운영 합의**(`22` §8.2).

1. ISMS-P·인증 심사 대비(요약)
   - ISMS-P는 관리체계·보호대책·개인정보 처리 등 통합 통제로, **세부점검항목·법령은 개정·갱신**되므로 심사 전 [ISMS-P 누리집](https://isms-p.or.kr/ntcn/rcsrm/selectGnrlRcsrmList.do)의 최신 안내서·세부점검항목(예: 2024.07 안내서, 간편인증 7의2·7의3 xlsx 등)과 본 서비스를 **직접 대조**하는 Gap 분석이 필요하다(본 문서는 법률 자문이 아니다).
   - 보호대책 **2.9.4 로그 및 접속기록 관리** 등과 정합: 로그 유형·보존기간·별도 저장(백업)·접근 최소화·위변조 방지, 개인정보처리시스템 **접속기록** 필수 항목·보존(법정 기간은 처리 규모·업종에 따라 상이) 및 **정기 점검** 절차를 운영 규정·제품 기능과 맞춘다.
   - 요약 참고: [ISMS-P 2.9.4 로그·접속기록 관리(요약)](https://itwiki.kr/w/ISMS-P_%EC%9D%B8%EC%A6%9D_%EA%B8%B0%EC%A4%80_2.9.4.%EB%A1%9C%EA%B7%B8_%EB%B0%8F_%EC%A0%91%EC%86%8D%EA%B8%B0%EB%A1%9D_%EA%B4%80%EB%A6%AC).
   - 본 제품 기준으로 심사·점검에서 자주 지적되기 쉬운 **개선 검토 요소**(과제 3·1과 연계해 증적 확보)
     - 개인정보·고객 데이터에 가까운 조회·다운로드·보내기 경로에 대해, 접속기록에 **수행 업무·대상 범위**를 식별할 수 있는지(쿼리 스튜디오·리포트·ETL 결과 등)
     - 로그·접속기록의 **보존 기간·백업·삭제 권한 분리·무결성**(운영자 임의 삭제 방지) 정책과 구현 일치
     - **월 단위 이상 징후 검토**(미로그인 관리자, 비정상 시간대 대량 조회 등) 절차와 담당
     - **침해사고·유출 의심 시** 대응 체계(내부 에스컬레이션, 정보주체 통지 필요 판단, 기록 보존)와 훈련
     - **백업·복구** 목표(RTO/RPO)·주기·복구 테스트 **증적**
     - **위탁·외주** 개발·운영이 있을 경우 계약상 보안 조항·점검 증적
     - 정책·절차 문서와 **실제 로그·교육·내부감사** 기록의 일치(형식만 갖춘 경우가 지적되기 쉬움)
