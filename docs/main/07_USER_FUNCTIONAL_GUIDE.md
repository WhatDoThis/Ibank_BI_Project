## 1. 서비스 한눈에 보기

- IBank BI(임시제목)는 마케팅 대시보드를 제공하고, 마케터용 노코드 쿼리 빌더(쿼리 스튜디오)로 CRM 리포트 데이터를 조회·집계·생성하는 데 초점을 둔다.
- 부서(조직) 단위로 계정이 나뉘고, 그 안에서 프로젝트를 선택한 뒤 대시보드·리포트(쿼리)·위젯 등 업무 화면을 쓰는 형태다.
- 최초 조직·관리자 계정은 운영사의 개발자 계정으로 부여되며 구성원은 초대로 가입한다.
- 대부분의 계정은 관리자(SA, A)가 보낸 초대를 받은 뒤, 초대 코드로 가입한다.
- 로그인은 이메일·비밀번호 인증(1차) + 이메일로 받은 인증 코드(2차) 를 통해 진행되는 2단계 인증방식이다.

## 2. 회원가입: 초대 코드로 가입

- 회원가입: 초대 코드로 가입


### 흐름 설명

1. 관리자가 보낸 메일의 링크를 열거나, 안내받은 초대 코드를 준비한다.

2. 1) 링크를 열면 화면에 자동으로 초대 코드가 입력 되고, 이메일·비밀번호 등을 입력하고 가입을 완료한다.
   2) 링크가 열리지 않을 경우 회원가입 창에서 초대 코드를 직접 기입하고 가입을 진행한다.

3. 이후 로그인 화면에서 2차 인증을 거쳐 접속한다.


### 회원가입 화면 구성과 동작

1. 초대 코드
  - 메일 링크로 들어온 경우 코드가 자동으로 채워진다.
  - 입력란에 코드를 넣고 입력란 밖을 클릭(포커스 이동)하면, 코드가 유효한지 확인하고 부서·역할 안내 문구가 나타날 수 있다.

2. 이메일
  - 초대가 발송된 주소와 같아야 가입이 된다.

3. 비밀번호 / 비밀번호 확인
  - 안내 문구에 적힌 규칙(길이·영문 대·소문자·숫자·특수문자 등)을 만족해야 한다.

4. 비밀번호 조건·일치 검증
  - 누르면 두 비밀번호가 같은지·규칙을 통과하는지 미리 확인만 한다. 가입 완료 버튼은 아니다.

5. 닉네임(선택)
  - 화면에 표시될 이름에 가깝게 쓸 수 있다.

6. 가입하기
  - 가입 처리가 진행된다.
  - 성공하면 로그인 화면으로 이동하며, 안내 문구로 가입 완료를 알려 준다.


### 초대 코드 사용완료 혹은 만료시(7일)

- 코드가 이미 사용됨·만료이면 안내 문구로 알려 준다. 이 경우 관리자에게 **새 초대**를 요청한다.

## 3. 로그인

- 로그인: 이메일·비밀번호·인증 코드(2단계)


### 로그인 화면 구성과 동작

1. 이메일 / 비밀번호

 - 이메일과 비밀번호를 입력하고 「인증 코드 받기」를 누른다.
 - 비밀번호가 맞고 계정이 사용 가능한 상태(활성)면, 등록된 이메일(또는 운영 정책에 따라 안내된 경로)로 숫자 인증 코드가 발송된다.
 - 잘못된 비밀번호, 정지·잠금된 계정이면 오류 메시지가 표시된다.

2. 인증 코드 입력

 - 이메일로 받은 숫자 인증 코드를 입력한 뒤 「로그인」을 누른다. 코드가 맞으면 접속이 완료되고 프로젝트 선택 화면(홈)으로 이동한다.
 - 「← 이메일로 돌아가기」를 누르면 다시 이메일·비밀번호 입력 단계로 돌아간다.
 - 화면 하단에는 초대 코드로 가입 화면으로 가는 링크가 있다.


### 인증 코드·인증 토큰 만료시(5분)

 - 서버에 저장된 인증 코드 유효 시간이 지나면 인증이 실패한다(기본 5분).
 - 1단계 직후 화면에 내려오는 일회용 인증 정보도 설정(분) 안에서 만료되며, 둘 중 먼저 끝나는 쪽에 막힐 수 있다.


### 가입 직후·비밀번호 변경 직후 로그인 화면

가입을 마친 직후에는 로그인 화면 상단에 「가입이 완료되었습니다. 로그인해 주세요.」가 보일 수 있다. 마이페이지에서 비밀번호를 바꾼 뒤에는 「비밀번호가 변경되어 모든 세션이 종료되었습니다. 다시 로그인해 주세요.」가 보인다(로그인 화면 플래시 영역).

## 4. 로그인 후 공통 화면

- 왼쪽 메뉴·상단 헤더·현재 위치 표시


### 네비 - 주 메뉴에 보이는 항목

1. 프로젝트
 - 누르면 참여 프로젝트 목록 화면(`/`)으로 간다.

2. 사용자 관리·권한 관리·프로젝트 관리·부서 관리
 - 계정 역할에 따라 보이거나 숨겨진다. 해당 페이지들의 자세한 설명은 [11. 관리 메뉴]에서 확인 가능하다.

3. 쿼리 스튜디오·대시보드·위젯보드
 - 프로젝트 페이지 혹은 헤더의 프로젝트 드롭다운에서 작업할 프로젝트를 먼저 선택해야 사용 가능하다.
 - 프로젝트 선택 전에는 보이지 않는다.

4. ETL
 - 데이터 연동·적재 권한이 있는 ETL 관리자 계정에만 보인다. 자세한 설명은 [10. ETL]을 본다.


### 상단 헤더 구역

1. 현재 페이지 제목
 - 지금 열려 있는 화면 이름이 좌측 상단에 표시된다.

2. 로그인 이메일
 - 접속 중인 계정 이메일 주소가 보인다.

3. 작업 프로젝트 선택
 - 드롭다운에서 고르면 이후 대상 프로젝트로 변경된다.

4. 알림
 - 종 모양 아이콘. 목록을 열고 알림 내용에 따라 수락/거절 등이 가능하며, 관련 화면으로 갈 수 있다.

5. 마이페이지
 - 닉네임 변경·비밀번호 변경·로그인 이력 확인이 가능하다.

6. 로그아웃
 - 누르면 이 브라우저 세션이 끊기고 로그인 화면으로 돌아간다.


### 가로 경로(브레드크럼)

- 상단 헤더와 콘텐츠 사이에 IBank BI / (현재 화면 이름) 형태로 지금 위치가 한 줄로 보인다.

## 5. 프로젝트(홈)

- 홈: 작업할 프로젝트 조회 및 선택.


### 프로젝트 목록 구성과 동작

1. 카드 목록
 - 참여 중인 프로젝트가 카드형태 목록으로 제공된다(넓은 화면에서는 한 줄에 두 카드, 좁으면 한 줄에 한 카드).
 - 카드별로 프로젝트명, 프로젝트 권한(역할) 라벨·이름, 프로젝트 설명이 보인다.

2. 이 프로젝트로 작업
 - 누르면 헤더의 드롭다운이 해당 프로젝트로 지정되고, 권한에 맞는 페이지가 네비에 활성화 되며 해당 페이지로 이동할 수 있다.

3. 헤더 프로젝트 드롭다운
 - 이미 선택된 작업 프로젝트가 있으면, 홈으로 돌아와도 헤더에서 바로 다른 프로젝트로 바꾸거나 같은 프로젝트로 이어 갈 수 있다.


### 상단 안내·빠른 액세스

1. 상단 문단

 - 프로젝트를 고르면 이후 화면에 그 프로젝트 권한이 적용된다는 뜻을 설명한다.

2. 프로젝트 작업 카드

 - 작업 프로젝트를 고른 뒤에만 쿼리 스튜디오·대시보드·위젯보드 카드가 쓸모 있게 열린다.
 - 해당 프로젝트에 권한이 없으면 권한 없음에 가까운 안내가 나올 수 있다.

3. 관리·인프라 카드

 - 역할에 따라 사용자 관리, 권한 관리, 프로젝트 관리, 부서 관리, ETL 바로가기가 나타난다.


### SA·A·O·U에 따라 달라지는 점

1. U·O

 - 목록에는 본인이 참여한 프로젝트만 보이는 경우가 많다. 비어 있으면 SA 또는 A에게 프로젝트 참여 초대를 요청한다.

2. SA·A·O

 - 프로젝트 관리 바로가기 카드는 세 역할 모두에 보일 수 있다. O는 SA·A보다 만들기·삭제·테이블 연결 등이 제한될 수 있다. [11.3 프로젝트 관리](#113-프로젝트-관리)를 본다.

## 6. 마이페이지

- 마이페이지: 내 프로필·비밀번호·접속 이력


### 화면 구성과 동작

1. 프로필(이메일·부서·역할·닉네임)

 - 이메일·소속 부서·조직 역할 코드는 읽기 전용이다.
 - 닉네임을 고친 뒤 「닉네임 저장」을 누르면 확인 창 후 서버에 반영된다.

2. 비밀번호 변경

 - 현재·새·새 확인 비밀번호를 입력해 변경한다.
 - 성공 시 **모든 기기·브라우저에서 로그아웃**되며 다시 로그인해야 한다. 확인 창에도 같은 안내가 있다.

3. 로그인 이력

 - 최근 접속 시각 등이 표로 나온다.

## 7. 쿼리 스튜디오

- 쿼리 스튜디오: 테이블을 골라 CRM 리포트(조회) 만들기


### 화면 구성과 동작

1. 왼쪽(테이블·폴더)

 - 쓸 수 있는 테이블·폴더가 트리로 보인다.

2. 가운데(조건 조립)

 - 열 선택, 필터, 정렬, 실행 등으로 조회를 만든다.

3. 아래(결과)

 - 실행하면 표 형태로 결과가 채워진다. 실행 전 확인이나 제한 안내가 있을 수 있다.

4. 저장·불러오기

 - 조회를 이름 붙여 저장해 두었다가 나중에 다시 연다.


### 쿼리 스튜디오를 쓸 수 있는 조건

- 프로젝트 멤버 권한(읽기만, 실행 포함 등)에 따라 메뉴·실행이 열리거나 막힌다. 권한이 없으면 메뉴나 화면이 보이지 않을 수 있다.

## 8. 대시보드

- 대시보드: 캠페인·마케팅 성과 보기


### 화면 구성과 동작

1. 차트·지표

 - 헤더에서 고른 작업 프로젝트 기준으로 차트·숫자 카드가 나온다.

2. 기간·필터

 - 화면의 기간·필터로 보고 싶은 범위를 바꾼다. 항목 이름은 배포 버전에 따라 다를 수 있다.


### 대시보드 메뉴가 보이는 조건

- 프로젝트 설정에서 기능이 켜져 있고, 멤버 권한 템플릿에 대시보드가 들어 있어야 한다.

## 9. 위젯보드

- 위젯보드: 보드 목록과 보드 편집


### 보드 목록(`/widgetboard`)

1. 목록

 - 프로젝트에 만들어 둔 보드가 나열된다.

2. 새 보드

 - 버튼이 있으면 이름·설명을 넣는 창이 뜬 뒤 목록에 한 줄이 추가된다.


### 개별 보드 편집(`/widgetboard/숫자`)

1. 캔버스

 - 차트·표 등 위젯을 놓고 격자에 맞춰 크기·위치를 조정한다.

2. 데이터 연결

 - 테이블·열 설정으로 위젯을 채운다.

3. 상단·도구줄

 - 저장, 미리보기, 목록으로 돌아가기 등이 모여 있다.


### 위젯보드 메뉴가 보이는 조건

- 멤버 권한에 위젯보드가 포함된 계정만 쓸 수 있다.

## 10. ETL(데이터 가져오기·연결)

- ETL: 파일·외부 DB·폴더에서 데이터 가져오기


### ETL 메뉴가 보이는 계정

- 조직에서 데이터 적재·외부 연동 담당으로 등록된 계정에만 좌측 메뉴가 보인다.


### 화면 구성과 동작(상단 탭)

1. 파일 업로드

 - CSV·엑셀 등을 올리고 저장 위치를 정한 뒤 반영한다.
 - 「탭 요약 · 사용 안내」를 펼치면 단계 설명이 있다.

2. 타겟DB 연결

 - 외부 DB 접속을 등록하고 테이블을 골라 적재한다.

3. 배치폴더 등록

 - SFTP·S3 등 폴더를 등록하고, 규칙에 맞는 파일이 올 때 자동 적재되게 한다. 배치 목록과 실행 이력을 같은 화면에서 본다.

4. 저장DB 등록

 - 적재 대상 PostgreSQL 연결을 등록·연결 테스트한다. 목록 맨 위에 기본 저장 위치가 보일 수 있다.

5. ETL 이력

 - 진행·완료·실패 등 상태를 보고 필요 시 항목을 지운다.


### 추가로 열리는 창

1. 미리보기

 - 적용 전 일부 행만 골라 내용을 확인하는 창이 뜰 수 있다.

2. 파일 추가·이력 상세

 - 파일 단위 설정이나 과거 로그를 자세히 보는 창이 열릴 수 있다.

## 11. 관리 메뉴

### 11.1 사용자 관리

- 사용자 관리: 부서원·초대·계정 상태


1. 목록·초대·상태

 - 같은 부서(및 허용 범위) 사용자가 표로 나온다.
 - 초대로 이메일·부서·역할을 넣는 창을 연다. 보내기 전 확인, 완료 후 안내가 나온다.
 - 행마다 변경·정지·활성·삭제·강제 로그아웃 등이 있을 수 있다.
 - 정지·삭제가 막히면 이유와 다음 단계(이관 등) 안내 창이 뜬다.

2. 사용자 변경 창

 - 부서·조직 역할·프로젝트 참여를 한 화면에서 고친다. 저장 전 확인.
 - 데이터 적재 담당 스위치 등은 SA만 바꿀 수 있는 경우가 있다.

3. 이 메뉴를 쓰는 역할(SA·A)

 - SA와 A만 들어간다. A는 다른 A·SA를 바꾸지 못하게 막힐 수 있고, 정지·활성은 보통 O·U 위주로만 허용된다.


### 11.2 권한 관리

- 권한 관리: 프로젝트 권한 묶음(템플릿)


1. 템플릿 목록·체크박스

 - 멤버에게 줄 권한 묶음을 이름 붙여 만든다. 쿼리 읽기, 대시보드, 위젯보드 등을 체크박스로 조합한다.
 - 새로 만들기·수정으로 이름·설명·체크박스 폼이 열린다. 저장 시 확인이 있을 수 있다.

2. SA와 A의 차이

 - SA와 A가 쓴다. A는 우리 부서 커스텀 템플릿만 다루는 경우가 많다.


### 11.3 프로젝트 관리

- 프로젝트 관리: 만들기·설정·멤버


1. 새 프로젝트·수정·비활성

 - 새 프로젝트는 이름·설명·부서·권한 템플릿·연결 테이블 등을 한 번에 넣는 큰 창이 열릴 수 있으며 단계마다 확인이 뜬다.
 - 수정은 같은 창의 탭에서 이름·매핑·기능 켜기/끄기를 고친다. 저장 전 확인.
 - 비활성·활성은 확인 후 목록·업무 메뉴 반영이 바뀐다.

2. 멤버 관리

 - 목록에서 프로젝트를 고른 뒤 멤버 화면으로 들어가 초대·권한 변경을 한다.

3. SA·A·O가 각각 할 수 있는 범위

 - 메뉴는 SA, A, O가 본다. 만들기·삭제·테이블 연결은 SA·A 중심이고, O는 참여 프로젝트에서 이름·설명·멤버 일부만 할 수 있다.


### 11.4 프로젝트 멤버

- 프로젝트 멤버: 참가자·초대·수락 전


1. 표·초대·수락 전

 - 참여 중인 사람이 표로 나온다. 초대만 보내고 수락 전인 사람은 따로 구분될 수 있다.

2. 멤버 추가·권한·제외

 - 멤버 추가는 조직 사용자와 권한 템플릿을 고른 뒤 확정한다.
 - 권한 변경·제외는 확인 후 반영된다.

3. O가 쓸 때

 - SA·A는 부서 범위에서 넓게 쓰고, O는 운영 권한이 있는 프로젝트에서만 쓴다.


### 11.5 부서 관리

- 부서 관리: 조직 트리


1. 트리·추가·이름·삭제

 - 하위 부서 만들기, 이름 바꾸기, 삭제는 대부분 확인을 거친다.
 - 다른 데이터에 묶여 삭제가 안 되면 안내만 보이고 취소된다.

2. SA만

 - 부서 최고 관리자(SA)만 이 화면을 쓴다.
