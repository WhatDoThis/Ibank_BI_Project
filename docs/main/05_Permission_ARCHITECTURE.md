
# 권한·역할 아키텍처 (최종 v2)

**용도**: 조직 역할(`user_info.user_dvsn`)·프로젝트 역할(`pmssn_master`)·ETL 인프라 접근을 한 문서에서 정의한다. 세부 고객 여정은 **`06_CUSTOMER_JOURNEY.md`**, DB는 **`04_DB_ARCHITECTURE.md`**, 구현 가이드는 **`docs/report/17_SystemDB_Commercialization_Implementation_Guide.md`** 를 본다.

---

## Role 체계 (6단계)

| 코드 (DB) | 약어 | 설명 |
|-----------|------|------|
| `sa_dev` | SA_DEV | 개발자(단일 계정, `dptmt_info_id=0`) |
| `super_admin` | SA | Super Admin(부서장) |
| `etl_manager` | E | ETL Manager(전사 ETL 전담, 부서 무관) |
| `admin` | A | Admin(부서 관리자) |
| `operator` | O | Operator(프로젝트 운영자) |
| `user` | U | User(일반 사용자) |

`user_info.user_dvsn` 값: `sa_dev` / `super_admin` / `etl_manager` / `admin` / `operator` / `user`

## 권한 매트릭스 (최종 v2)

SA_D = SA_DEV | SA = Super Admin | E = ETL Manager | A = Admin | O = Operator | U = User

✓ = 항상 가능 | ○ = 조건부 가능 | - = 불가

### 1. 부서 관리

| | SA_D | SA | E | A | O | U |
|--|:----:|:--:|:--:|:--:|:--:|:--:|
| 최상위 부서 생성 | ✓ | - | - | - | - | - |
| 본인 부서 하위 부서 생성 | - | ✓ | - | - | - | - |
| 부서명 수정 | ✓ | ○ | - | - | - | - |
| 하위 부서 삭제 | ✓ | ○ | - | - | - | - |
| 전체 부서 목록 조회 | ✓ | - | - | - | - | - |
| 본인 부서 + 하위 부서 조회 | - | ✓ | - | - | - | - |

※ SA_D: 전체 부서 CRUD. SA: 본인 부서 기준 하위만 생성·수정·삭제·조회.

### 2. 회원 초대 (가입 초대코드 발송)

| | SA_D | SA | E | A | O | U |
|--|:----:|:--:|:--:|:--:|:--:|:--:|
| E로 초대 | ✓ | - | - | - | - | - |
| SA로 초대 | ✓ | ✓ | - | - | - | - |
| A로 초대 | ✓ | ✓ | - | - | - | - |
| O로 초대 | ✓ | ✓ | - | ✓ | - | - |
| U로 초대 | ✓ | ✓ | - | ✓ | - | - |

※ E 초대: SA_DEV만. SA 초대 시 해당 부서에 이미 SA 있으면 컨펌. A의 선택지에 SA·E 미노출(백엔드 제어). O·U: 가입 초대 불가.

### 3. 유저 관리

| | SA_D | SA | E | A | O | U |
|--|:----:|:--:|:--:|:--:|:--:|:--:|
| 전체 유저 조회 | ✓ | - | - | - | - | - |
| 본인 부서 유저 조회 | ✓ | ✓ | - | ✓ | - | - |
| 유저 정지/활성 전환 | ✓ | ✓ | - | ○ | - | - |
| 유저 강제 로그아웃 | ✓ | ✓ | - | ○ | - | - |
| 유저 role 변경(부서 레벨) | ✓ | ✓ | - | ○ | - | - |

※ SA: 본인 부서 전체. A: A 이하(O, U)만 정지·활성·강제로그아웃·role 변경. A는 SA·E·타 A 변경 불가.

### 4. 역할·권한 정의

| | SA_D | SA | E | A | O | U |
|--|:----:|:--:|:--:|:--:|:--:|:--:|
| 시스템 기본 역할 CRUD | ✓ | - | - | - | - | - |
| 부서 커스텀 역할 CRUD | ✓ | ✓ | - | ○ | - | - |

※ A: 본인 부서 커스텀 역할만.

### 5. 프로젝트 관리

| | SA_D | SA | E | A | O | U |
|--|:----:|:--:|:--:|:--:|:--:|:--:|
| 프로젝트 생성 | ✓ | ✓ | - | ✓ | - | - |
| 프로젝트 삭제 | ✓ | ✓ | - | ✓ | - | - |
| 프로젝트 수정(테이블 매핑) | ✓ | ✓ | - | ✓ | - | - |
| 프로젝트 수정(명/설명) | ✓ | ✓ | - | ✓ | ○ | - |
| 프로젝트 멤버 초대(기존 유저) | ✓ | ✓ | - | ✓ | ○ | - |
| 프로젝트 멤버 강퇴 | ✓ | ✓ | - | ✓ | ○ | - |
| 프로젝트 멤버 권한 변경 | ✓ | ✓ | - | ✓ | ○ | - |

※ SA_D: 전 부서. SA·A: 본인 부서. O: 본인 참여 프로젝트만, 권한 변경은 U만.

### 6. ETL 관리 (전사 공통)

| | SA_D | SA | E | A | O | U |
|--|:----:|:--:|:--:|:--:|:--:|:--:|
| ETL 커넥션 CRUD | ✓ | - | ✓ | - | - | - |
| 스토리지 커넥션 CRUD | ✓ | - | ✓ | - | - | - |

| ETL 테이블 등록·변환룰 | ✓ | - | ✓ | - | - | - |
| ETL Job 생성·삭제·실행 | ✓ | - | ✓ | - | - | - |
| 배치 Job·실행·이력 | ✓ | - | ✓ | - | - | - |

※ E: 전사 ETL 전체. SA_D: E와 동일 + 시스템 관리. SA·A·O·U: ETL API 접근 불가(프로젝트 `pmssn`의 `etl` 권한과 무관).

### 7. 테이블 매핑(프로젝트)

| | SA_D | SA | E | A | O | U |
|--|:----:|:--:|:--:|:--:|:--:|:--:|

| 프로젝트↔테이블 매핑/해제 | ✓ | ○ | - | ○ | - | - |

※ SA·A: 본인 부서 프로젝트 생성·수정 시 매핑. E: 조회만.

※ SA_D·SA·A: 참여 프로젝트에서 보고 기능 자동 부여. O·U: `pmssn_master` 권한. **E**(`etl_manager`): 프로젝트 기능 접근 불가.

## 백엔드 구현 메모 (요약)

- **ETL `/api/etl/*`**: `user_dvsn ∈ {sa_dev, etl_manager}` 만 허용(프로젝트 선택·`pmssn` 불필요).
- **리포트·대시보드 등 프로젝트 기능**: JWT에 `project_info_id` 필요. `etl_manager` 는 403. `sa_dev`·`super_admin`·`admin` 은 참여 프로젝트에서 `report.read` 등 프로젝트 권한 자동 부여(매트릭스 §8).
- 상세: `Backend/auth_server/permissions.py`, `Backend/api_server/main.py`.
